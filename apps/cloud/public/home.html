Made for the room

Real people, one table, no one staring at a TV.

1

The board lies flat in the middle

A touchscreen everyone can reach: dice roll, cards slide, pieces move under your finger. Each seat has its own edge, and the board turns its text toward whoever is playing.

2

Your phone is your hand

Scan the QR code and you have a seat. No app and no account. Your cards, dice cup and bets stay on your phone; the table sees only what it should.

3

Empty seats? Add an AI

Every game ships with AI players, some with several styles. They play at the board's pace and wait for the animations, so they feel like people at the table.

Someone couldn't make it? Send an invite link. They see the same board in their browser with their own deck beside it, connected straight to your table. Up to four can join from afar, as players or as watchers.

Free games

The lobby

Real life at the table, handled for you.

Phones run out of battery, people leave early, a friend joins halfway through. The platform deals with all of it, so a game only plays the game, and every game behaves the same way.

Join by QR code

One code for everyone at the table. When no seat is free, the board and the phone say so.

Seats and colours

2 to 8 seats around the edges, each with a name and colour; the board turns toward each side.

Away phones keep their seat

A locked screen or a dead battery doesn't end the game. The seat waits, then the table decides.

Exchange a player

Mid-game, hand a seat to someone at the table, a remote friend, a watcher or an AI. The game carries on.

Remote invites

A link, optionally with a name. The browser connects straight to the table over WebRTC.

Watchers

Friends can follow along without a seat. Tap the eye to see who's watching, let them play, or remove them.

Rejoin by name

Left by accident? Scan again with the same name and you're back in your seat.

Logs, replay, viewer

Every game is logged and replayed to check it. The board's Game Viewer walks through each move.

For game developers

You bring the idea.
The platform brings the table.

The platform is made for agentic coding. You focus on the game idea, its design and the experience at the table; your AI agent writes the code. A game is a folder: a manifest, pure TypeScript rules, and optional board and phone screens in plain JavaScript. The developer guide is written for language models first, so your agent can read the contract and build a complete game.

“Create a backgammon game for the game platform.”

That was the whole prompt. Claude read the developer guide and came back with a working Backgammon, without anyone looking over its shoulder. A few hours of polish later it plays matches to 100 points with the doubling cube and the Crawford rule. Everything else it simply gets from the platform:

  • A touch board: tap, then move
  • Private phone decks

  • Logs, replay and statistics

Five steps from idea to table

Tell your agent
1

Start from a working repository

Copy extra-games: five complete games, tests that run them on the real platform, and CI. Or start inside the platform from games/coin-flip, the smallest complete game.

2

Let your AI read the contract

llms.txt points to the developer guide: the manifest, every rules hook, what the platform does with players, and a checklist. One file holds it all: llms-full.txt.

3

Write rules, not plumbing

Rules are pure functions on a JSON state: setup, onIntent, view, boardView, isOver, plus an AI. Randomness comes from the context, so every game can be replayed and checked.

4

Play it, even without a phone

Run a table on your laptop. Play from the board puts a player's deck beside the board, AI players take the other seats, and the Game Viewer shows each move if something looks wrong.

5

Bring it to every table

Your repository's games/ folder becomes an extra-game repository: clone it into a local table, or let a game service install it on its tables.

import { defineGame } from "@game-table/sdk";

// Coin Flip, shortened: everyone guesses, then the coin flips.
export default defineGame<State>({
  setup(ctx, settings) {
    const seats = ctx.seats.map((s) => s.seat);
    const rounds = Number(settings.rounds);
    return { round: 1, rounds, seats, guesses: {}, scores: {} };
  },

  onIntent(state, seat, intent, ctx) {
    if (intent.name !== "guess") return { reject: "unknown move" };
    const guesses = { ...state.guesses, [seat]: intent.payload };
    const next = { ...state, guesses };
    return allGuessed(next) ? flip(next, ctx) : { state: next };
  },

  // Each phone sees its own seat; the board sees what is public.
  view: (state, seat) => ({ myGuess: state.guesses[seat] ?? null }),
  boardView: (state) => ({ round: state.round, scores: state.scores }),
  isOver: (state) => (state.round > state.rounds ? summary(state) : null),

  // AI players read the same view a phone gets, nothing more.
  ai: (view, seat, ctx) => ({
    name: "guess",
    payload: ctx.random() < 0.5 ? "heads" : "tails",
  }),
});

// flip() draws from ctx.random(), never Math.random():
// every game replays exactly, and the platform checks it.
// games/coin-flip/manifest.json (shortened)
{
  "id": "coin-flip",
  "name": "Coin Flip",
  "version": "2026.10.19.1",
  "players": { "min": 1, "max": 8 },
  "turnModel": "simultaneous",
  "seatLayouts": [2, 4, 6, 8],
  "dynamicPlayers": true,
  "settings": [
    { "key": "rounds", "type": "int", "min": 1, "max": 20, "default": 3, "label": "Rounds" }
  ],
  "ai": { "supported": true, "options": [] },
  "simulation": { "supported": true, "headless": true }
}

// The board shows the settings; the lobby checks the player count.

Demo game

Make the table your own: Mexican Train.

Mexican Train, in extra-games, is a demo for developers: a game that changes nearly everything you see and hear, and still lets the platform handle the lobby, the seats and the players. Copy any part of it into your own game.

  • A board that sizes itself. A train can grow to 47 tiles: it bends into rows, and the tiles shrink only as far as they must.
  • Animated backgrounds. Aurora, lava, plasma, fireflies, a starfield or clouds, drawn by the game itself; or a new one each round.
  • The platform's seat plates, restyled. Glass you can see the background through, glowing on the player whose turn it is.
  • Its own sound and music. Tile clacks and a train whistle, and tunes the game composes as it plays.
  • Rule options and table preferences. House rules picked when the game starts; tile faces, background and music changed any time from the board's settings.
  • Its own phone screen. Your hand, the trains you may play on and two taps to play, in the platform's phone layout.

Platform feature

The sling: push a card off your phone, onto the table.

A game can let players push a card up and off the top of their phone. While the finger is still on the glass, the board shows the card coming in at that player's edge; let go and it flies onto the pile. Drawn cards fly the other way. Last Card, the newest game in extra-games, is built on it.

  • Live, not after the fact. The phone sends the gesture as it happens, and every board, at the table or remote, shows the card at the right seat and the same angle.
  • Push, flick or let go. Off the top of the phone, flicked left, middle or right, or let go above a line under the game's status.
  • The rules still decide. The game says which cards may go and what a move means; a card that doesn't fit peeks out and bounces back with the reason.

Test and debug

Test without players. Debug with your AI.

You don't need four friends to find a bug. Fill every seat with AI players and let the games run, then hand the log to your AI and point it at the move that went wrong.

Game logs

Logs your AI can read

Every game, played or simulated, is saved as a zip: every move, the state at the end, and a README.md that explains the format to whoever opens it. Each game is replayed when it ends to check it reaches the same state.

Run a game service

Every table, one console.

A table plays fine on its own. Add a game service and your tables reach past the room: it runs on a server with a DNS name and HTTPS, and its admin console looks after every table that connects to it. This page comes from one.

A server with DockerA DNS nameHTTPSGoogle sign-in for admins
  • Remote players from anywhere. An invite link brings a player or a watcher to your table from any browser, not just from your WiFi. The service introduces them, then they connect straight to the table.
  • Many tables, approved by you. A new table shows a pairing code on its board for you to approve, or starts with an access code you issued: a token for one table, valid for a week, a year or for good. Disconnect a table, or revoke its code, at any time.
  • The games each table gets. Add extra-game repositories from GitHub, and tick which tables get them, one by one or with their access code.
  • Game logs for analysis. Every game and simulation sends its log to the service. Filter by game, table and date, download the zips, or give a pipeline or a Claude session a download token. You choose how long logs are kept.
  • This website. The service serves this page, the developer guide and llms.txt.

About

Human players first.

Game Table began with a do-it-yourself game table that friends built, and with a love of board games. Klaus and those friends kept coming back to one idea: a game platform designed for the people at the table, helped by computer graphics and a referee that never tires. The rules are observed automatically, and the chores, like setting up the board and keeping the game moving, happen by themselves. What matters is the people playing together.

The idea

  • The table is the centrepiece. One shared touchscreen in the middle, and each player's phone as a private deck for the games that hide cards, like poker.
  • Remote players, on the side. Friends far away can join, but there is no video, voice or chat in the game, on purpose. Talk to them the way you already do, with Google Meet or FaceTime running alongside.
  • AI players fill the seats. Mainly so that a game that needs a certain number of players can start at all.

The code

  • Prompted, not typed. The ideas went to Claude, and Claude Opus 5.5 developed all of the code, step by step. Every decision is in the decision records: who asked, why, and how it was built.
  • A platform, and games from anywhere. The platform and its lobby are separate from the games, with clear ways to bring in games from other repositories that fit the table.
  • The table stays at home. The game service's lobby lets remote players find their game through an invite link, without the game table itself being exposed to the internet.
  • Open. The project is hosted by Klaus's engineering company, Skylar Technology, and every source for a complete game runtime and development environment is public on GitHub.

Try it with your own AI agent. Ask it to set up a table on your computer and start playing, or to write a new game from a single sentence. Then play it, and ask the agent to fix whatever could be better: that fine-tuning is usually worth it. Your games can stay private or be shared with everyone.
